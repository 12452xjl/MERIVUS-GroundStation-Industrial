# 规划审阅逐机能量账单（430，静态交接）

## 516：新增近期原生SOC窗口依据标签

原`energyBasis`／`projectionBasis`说明函数识别`native-soc-decline-window`，明确仅下调已有估算，不称实测功率或续航保证；不新增操作控件、确认、轮询或权限。界面继续沿原主题和PlainText只读说明，UI/UX指导仅用于语义清楚和不把估算表现为认证，没有运行搜索脚本、预览、交互或布局验证。

本页没有新增完整窗口专用浏览器。完整`nativeBatteryDrainAdjustments`随既有energyPlan归档，并可在515备用出勤的完整审阅明细及工程完整报告中逐字段读取，不能把依据标签说成全Fleet动态耗电看板。窗口未知不补模型，真实源／耗能和Qt交互仍须工程师验证；未编译、运行、测试或刷机。下方为历史。

## 432：显式备用待命与接替路线预算

当前 `compiled-reserve-route-budget` 不再拿最长主机时长替代备用机方案。备用成员先在同一规划页保存 `reservePlan`（接替对象、待命方式、待命秒数、明确的耗电系数和三项速度），并填写自身 `start/returnTo`。入口与版本绑定详见 `FleetReserveEnergyPlanPanel.md`。

逐机账单新增展示是否要求 / 完成备用输入、拒绝原因、目标 ID、待命方式 / 秒数 / 系数 / 等效名义飞行秒数、进场 / 完整目标路线 / 目标停留 / 自身返程估计、共同任务时间下限、返程预留和目标路线哈希。缺值或 -1 仍显示未知，不把未完成当作零需求；完整标志也只表示本次预算结构适用，不认证续航或飞行。待命成本额外加入任务预算，不被共同任务时间下限吸收。地面待命系数必须显式大于零，不能默认没有耗电。

方案是备用起点到指定主机完整已编译出航 / 作业路线，再返回备用机自己的返回点，不是从故障断点续飞；原主机返程路径不成为备用机返程的默认值。目标可为当前任何非备用成员，后端仍会拒绝不受支持或没有明确有限路线的目标。旧版 `worst-primary-route-reserve-budget` 只作为历史参考显示，不满足新的完整输入要求。保留当前主备身份、失格行、分页和 431 原生电池来源 / 审批时效检查；没有新增自动调度或放行。

## 431：原生电池报告只读来源

账单新字段 `nativeBatteryEvidence` 来自 Scheduler 保留的有效原生 envelope；即使成员被能量、健康或拓扑条件拒绝也保留来源说明。界面在原有每机卡片中显示聚合状态、审阅采样时 sourceCurrent、本地收包年龄、系统/组件/电池 ID、槽数、known、原报告与扣龄后时长、来源 epoch 与内容版本。没有新增控件或读取操作，没有实时计时刷新；显示的是该次审阅采样的年龄，不是现在的年龄，也不证明远端传感器测量新鲜。

聚合状态同时提供中文原因及原始状态码；未绑定不称为已收到报告，过期提示重新获取并审阅，多推进明确缺少组合模型。来源文字优先按词换行，长UUID等无法容纳时允许词内断行，避免窄面板横向溢出；实际布局仍待工程师验证。

`autopilot-reported-estimate` 显示为飞控报告且已扣本地收包年龄的剩余时间估计，不称为实测或经标定续航。多个推进电池、未知用途、过期、失源、缺 envelope 不显示为可用；缺少摘要仅表示未记录/无效，不会给 legacy 输入补造原生证明。唯一 fresh 电池有百分比但无剩余时间时，静态续航/消耗率模型仍可单独估算，预测未知不冒充已知。源和拓扑证据是本机实际接收范围，不认证发送者或未报告的物理电池。

审批路径另行重新取 Registry 来源并检查报告内容/可用性及扣龄剩余时长是否仍覆盖原主备账单；这不更新本卡片或授予起飞许可。来源/内容变化、失效或跨过预算门槛须重新审阅。自然 age 增长和同内容重复收包不单独改变审批指纹。本批只做源码静态核对，工程师仍须验证消息、来源切换、过期、重复/不完整报告、未知与多电池、预算边界及窄屏长文本。

## 已知、未知和预算来源

每机展示任务预算、返程预留、总需求、可用续航、余量或短缺、输入电量、预测末端电量、`eligible/reason` 及替补复核建议。资格仅是该次能量筛选结果，不是任务或起飞许可。

余量与可用续航必须以 `energyEvidenceKnown` 为准：证据未知时 `marginSeconds = -1` 不显示为真实短缺；证据已知且余量为 -1 时则明确显示短缺 1 秒。预测必须以 `projectionKnown` 为准，不能用当前电量代替缺失预测。缺字段、空账单或未知形状不显示为能量充足。小于 0.1 秒的非零数值保留非零提示，避免舍入成零误导。

主任务的 `budgetDetails` 展示进场、作业、返程估计，出航/返程停留预算和含停留估计、任务时间下限、提供或默认返程预留及依据。缺少分项显示“未提供”，null/无效数字显示未知，不填 0。路线时序、电池模型及“返程预留等于真实路线时长”的认证标志按原值显示；停留是预算而非绝对到达时刻。

430 的旧版备用账单曾采用主任务中最长出航与最长返程预算；该分支现在仅用于识别历史参考，当前新增方案使用 432 的显式输入和实际派生预算。共同任务时限仍可能使多架预算相同，不承诺逐架物理精度或实飞续航。

组摘要显示能量/审阅状态、全组账单瓶颈、续航未知成员数量、已知成员累计短缺和 `shortfallComplete`。五种新状态提供中文说明并保留原状态码；`estimate-feasible` 仍是估算而非实际续航保证。瓶颈未知时不显示 unknown ID 0；短缺统计不完整时，累计值只是已知下界，累计为 0 也不能解释为全组无短缺。逐机短缺之和不是整组延误。后端原始原因文本以纯文本有界显示，空原因只表示无附加原因，不解释为空即通过。
