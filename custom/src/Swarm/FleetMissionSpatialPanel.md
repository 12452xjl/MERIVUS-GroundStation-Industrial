## 使用路径

`FleetMissionSpatialPanel.qml` 继续作为启动空间核对面板中的默认折叠子区。使用 439 的一次显式捕获、同一 `captureToken/sourceToken/binding` 和地图选择，不创建第二份任务来源或审批流程。既有启动参考 `view` 仍是原十五字段；外层投影现在为九字段，在 440 的 `missionReview={ok,error,view}` 之外新增独立 `jointReview={ok,error,view}`。两个结果由 Root 按同一捕获 token 缓存发布，不能把旧联合结果配给新捕获。

用户选择原计划成员，再查看规划出航、规划返程或本地协议项，每页最多八条。起始/终结动作、全部限制、原时序、归档空域报告及禁飞区原值可按需逐层浏览。第六类为“本次联合静态报告”，复用同一个字段浏览器。本组件没有写草稿、审阅、批准、上传、解锁、启动或停止飞机的接口。

## 原记录与完整任务边界

- 完整视图只接受与捕获 `binding.planId` 一致的原归档计划，不从当前区域草稿、余段提案、机载缓存、导入运行报告或 live Vehicle 拼装。
- 原生显示投影十七字段；每机十五字段；路线四字段；点十三字段；动作七字段；编码项九字段。最多 32 架执行成员，单机 2048 点/项，整组各 8192 点/项。
- 保留备用成员 ID 作为诊断，不因此将备用编译成 active 任务。路线来源范围 `member/plan-global` 原样显示；路线包装器、全局时间、点时间和成员/计划时序保留独立命名域。
- 几何与编码独立呈现；一个成员的几何不可用时保留其身份和原因。Builder 整组拒绝时不制造有效编码前缀，几何仍可独立查看。
- `rawItem/canonicalItem` 是原完整计划的本地真实 Builder 输出，不是机载回读或已发送报文证明。序号从零开始但不等于路线点索引，映射只取原生来源字段。
- 航向、停留、时长估计的未知值保持 `null`，不补零。`estimatedElapsedSeconds` 只是原始累计时长估计，是否包含停留由原来源决定；不是 ETA，也不证明时序已编码。原地理规划点为 WGS84/AMSL；AMSL 不是离地高。
- `DO_CHANGE_SPEED` 的保留零不当坐标。TAKEOFF、无限 HOLD、LAND 明确显示声明/编码已知状态、协议序号和坐标；HOLD 不解释为零秒或完成，LAND 不解释为已经落地。未解析至成员的默认执行配置不能由界面补成已声明动作。

完整 Builder 成功时，规划 `returnPath` 已生成相应航点请求；但它不是 RTL/HOME，也不证明已上传或机载内容一致。RTL 不补画 HOME 连线。

## 有界字段浏览

原空域报告和禁飞区历史输入可能含旧字段或无效元素，不能假定旧报告都满足当前 schema。界面只验证受限外层，内部使用纯文本逐层对象/数组浏览：每层每页最多八项，不常驻展开整份报告。长字符串超过 2048 字符时继续分段分页，不以截断文本冒充完整字段。

该浏览器可查看动作、原时序、原始 `sourceMetadata/sourceTiming/sourceSchedule`、所有限制、未编码要求、空域原报告和禁飞区原值，以及新联合报告的完整 `memberCoverage/segments/segmentSources/analysis/limitations`。展开原字段只说明它当时被记录，不赋予真实性或权限。`null`、`false`、数字零及空字符串相互区分。

冻结身份改变时重置成员、类别、页码和展开状态。完整视图验证绑定稳定的 `capture.missionReview` 与计划 ID；联合视图独立验证 `capture.jointReview`，不把当前性/遥测年龄更新转换成每次重新 stringify 整组 8192 项或 8320 段。显示控件只实例化当前八条数据；编码原值/量化差仅显式展开时构造文本。

## 空域报告的来源与范围

`airspace` 十二字段保留 `available/inputState/noFlyZones/zoneCount/minimumSeparationMeters/thresholdSource/report/scope/limitations` 和三个固定 false 认证标志。

- `available` 仅表示原报告可以展示，绝不等于风险通过。
- 输入区分已记录列表、当时省略、当时无效、旧记录未知。空列表或缺省不表示没有禁飞区，也不表示已加载权威空域；元素原值不等于已验证几何。
- `scope=archived-planning-routes-only`：仅原规划路线，不覆盖启动名义段、终结下降、RTL/HOME、动态时序、地形或障碍物。
- 原报告实际应用间距可能源于更严格的历史任务/审阅配置，不等同 439 启动候选所取的明确计划间距。两个阈值不能互换；442 的新联合静态分析独立列出自己的实际阈值和来源，不改写原归档报告的范围。
- 空域原值不在地图上重新画成“已验证禁飞区”；逐层字段可完整查阅，所有认证仍为 false。

## 本捕获的联合静态报告

联合结果接受固定三字段信封、二十二字段 view、十二字段逐机范围摘要、二十一字段 analysis。只有 `planId` 对应捕获 binding、`reviewKind/reviewId/reviewFingerprint` 对应同一启动视图、完整成员顺序对应本捕获时，才展示计算摘要。原计划视图可用时额外核对其全部成员顺序；不从最近一次成功结果、当前地图或其它成员补值。

- `coverageComplete` 是表示范围是否齐备；`comparisonComplete` 是已表示几何的计算是否全部完成。二者分开显示，不能合成“通过”。本地 canonical 请求链和独立启动假设不是实际连续航迹。
- 摘要分别显示段数、参与计算机数、区域数、已比较段对、段/区域比较数、接近候选和区域命中。计算未完成时，候选/命中总数显示未知，并保留原字段计数供解释；不把失败结果中的零当作已排除风险。
- 候选和命中明细各最多 512 项，显示保留条数、完整计数与各自截断标志。细节截断不等于比较未完成，比较完成也不等于表示范围齐备。仅有界浏览原值，不在 QML 重算几何。
- 所选成员显示实际编码/执行配置可用性、启动几何状态、编码请求段/启动假设段计数、TAKEOFF 序号对应检查和原生缺口原因。全组 `memberCoverage` 保留在第六类逐层分页中，不常驻创建 8320 个条目控件。
- 新报告缺失、原生拒绝、字段不完整或身份不一致时显示明确原因，不借旧报告。该提示和浏览器在原计划 `available` 分组之外，原计划失败不会隐藏联合错误；联合失败也不使原计划消失。
- 第六类只读展开不选择地图、不更换图层、不恢复任何批准，不改变飞行操作门禁。零候选/零命中不是无风险，地形、净空、动态四维时序、实际起降轨迹和机载内容仍未认证。

## 地图图层与隔离

`FlyViewMap.qml` 接受升级后的九字段捕获外层；新增联合报告不是第四个图层，也不是地图选择依据。选中同一次捕获后，地图仍使用三个独立显示层：启动名义参考、完整原计划出航/规划返程、声明 TAKEOFF/HOLD/LAND 请求。可选择全部或单独一层；切层只影响显示并推进原交互代次，不重新审阅或发送命令。

启动层保留 439 的每机合并高度卡。计划层最多每成员两条路径与一个摘要标记，不为 8192 个点逐一创建标记。动作层只画明确地理动作，同机同 XY 的多个动作合并，保留各自 AMSL 高度和编码状态；动作卡置于坐标右下，计划摘要置于左下，启动卡位于上方，避免同 XY 完全覆盖。底图上的邻近不同成员仍可能拥挤，需工程师验证实际布局。

完整任务层不可用时明确显示缺口，不回退旧 area/remainder；可保留同捕获的启动参考层。反过来，启动几何未知时也可查看合法的原计划层，定位按钮按当前显示层选择首个已知点，只移动地图视野。439 启动接近候选不因加入完整路线图层而扩展为全任务冲突检查。

保留现有 sourceKey、按压 epoch、完成创建后的同步、同步票据尾核、退出恢复与 GoTo/Shift/框选隔离。原规划编辑器实例不重建，未提交文本不静默丢失。结束查看不停止飞机，也不改变原生启动事务。
