# 规则建议待审箱

指挥中心的“规则建议待审箱”接入私有 `FleetEventRuleEngine` 的实际黑匣子实时接收链。它保留本次会话尚未处理的建议，不因下一条事件未命中或时间轴回放而清空。旧 `eventRuleSuggestions` 仍只是最近一次评估的兼容投影，不作为待处理数量。

操作员按四条分页选择建议，查看原始事件、规则定义和建议动作的纯文本 JSON 分片（每片最多 2048 UTF-16 单位，不截断代理对），填写最多 512 字符的处理说明，再明确选择“已审阅”或“拒绝”。提交时冻结并核对原对象、会话、建议 UUID、修订与说明；原生端精确比较后只移出该条待审建议。当前 UI 对两种处理均要求说明，提交去除首尾空白；原生非法控制字符仍拒绝。

成功回执分别尝试记入既有黑匣子和证据链。界面分别显示它们是否接收，不把接收视为磁盘持久化。原生处理已提交后，审计失败、界面关闭或对象替换都不撤销该处理；回执未知时要求核对列表，不自动重试。待审箱最多 64 条、每条完整快照最多 128 KiB、累计编码最多 4 MiB；整次事件超限会明确拒绝入箱，不自动删未处理项。处理后释放空间，不另建隐含终态历史。

“前往任务规划”只触发现有规划视图导航，不把任意规则 `action` 翻译成任务，不替换草案，不发返航、暂停、起飞或其他指令。查看或处理建议不是批准，也不证明问题解除。历史回放与实时冷却分别保存；`fleet.rule_review.` 审计事件不会递归生成新待审项。重启不恢复待审箱。

UI 沿用 Qt/QGC 控件与调色板，弹窗有可见关闭和 Escape 返回、单滚动区域、键盘焦点、纯文本长字段换行、加载/错误提示。未运行界面或测量主题对比度。工程师须验证键盘与触控、实际 Qt 版本、相邻事件/回放隔离、满箱原子拒绝、同条重复处理、来源替换/销毁、同步通知重入、处理后审计失败和全量上限性能；全部未执行。
