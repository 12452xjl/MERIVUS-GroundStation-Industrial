# FleetMissionDraft - local map-planning draft

## 537：逐辅助 NAV 航点的可选相对驻留

沿536同一个真实独立路线编辑入口，relay／responder 的 `waypoints`／`returnPath` 点现在还可独立保留可选 `holdSeconds`。它只接受实际非null、有限的 Int／UInt／LongLong／ULongLong／Double 数值，范围 `0..86400` 秒（两端包含），且须符合下述统一非零编码政策，规范存原请求Double；String、Bool、typed-null、Float／custom、NaN／Inf、负数和超界值整点拒绝。没有 `hold`／`dwell`／其它驻留别名，也不接受数字字符串。缺失不补0；显式0仍有字段、保留在源／任务身份中，不能与没有明确驻留要求合并。

Draft对实际提供的holdSeconds调用共享 [DwellEncoding](FleetMissionDwellEncoding.md) `encode(value,Value&)`，不另写Float公式。实际正请求若转Float32或模型中的PX4整数微秒等待后为0即整点拒绝，不夹大、不改为0，不输出可用成功前缀；明确0仍合法。只把 `Value.requestedSeconds` 存回本点，`uploadSeconds`、`modelWaitMicroseconds`、`budgetSeconds`不替代原请求，实际预算与编码由相同helper的消费者使用。append／update的native错误明确指出hold字段和有限范围／正值归零限制，UI原 `lastError` 路径显示原因且保留输入；存储全份恢复同样验证这一政策，不能从历史点绕过。

原点归一化的内部开关改名 `routeOptionsAllowed`，只在独立路线的 append／整点update／stored source验证路径开启。区域顶点、排除环、`start`／`returnTo` 端点仍拒绝 `holdSeconds`，不把它用作起飞、降落、HOLD动作或自动覆盖点政策。独立 `heading` 与 `holdSeconds` 可分别缺失／提供，二者全部合法后才由原单次commit提交；坏最后字段不安装成功前缀或把旧字段补成默认值。

规范 stored point 为原五个坐标／参考字段，加相互独立可选 `heading`／`holdSeconds`。全体保留路线（含角色变更后的非激活路线）继续完整校验。`planningSource`、editing／planning 两种validator、pristine restore、名单／角色保留及 `buildTask` 的原 assignments 完整携原秒数；outer source schema1..6及其settings版本选择不变。旧无驻留点逐值保持；不靠剥字段加载新源。旧完整validator会拒绝此前不支持的额外holdSeconds，不能称旧版本自动兼容新要求。

536既有 `updateMemberWaypoint` 与Facade精确revision／sourceToken门不增接口。它仍完整替换一个原索引点：本次point没有holdSeconds就移除该点旧显式驻留，保留则存本次值，不将缺失解释为“合并旧值”。不改其它点、路线顺序、heading选择或点数预算。正常commit＋1后按原后置来源核验清掉已保存输入；过期／换源／通知重入或销毁的false不当回滚或自动重试依据。

Planner新增独立“为这个NAV航点指定相对驻留”勾选项和带秒单位／范围label的数值框；只有明确勾选才在本次点中提供holdSeconds。回填已有点时按字段存在恢复勾选与原文本，包括0；“保存本点修改”同时保存该点坐标、原heading选择和hold选择，“放弃本点输入”只丢未提交文本。仅改驻留或只勾选也计pending，复用同一个原Draft／controller／selection／revision／成员／路径／索引会话，不沿旧值预览、批准、保存或切成员／路径。外部换成空草稿或非辅助成员后，旧输入和明确放弃仍可达，不能误保存到新源。

原路线列表逐点显示“驻留未明确要求”、明确0秒或原正秒数；不把缺省当已确认零，不在QML另算飞行结果。新控件沿原Qt／QGC palette、可见label、键盘焦点／滚动可见性和失焦／保存后的就地错误；放弃按钮一直保留。QML仍只做有限十进制与0..86400范围检查，不复制Float32／微秒运算；持续帮助文字说明极小正值归零会在原生保存拒绝，须按具体错误调整，不能沿旧值保存。持续说明这是**到达该NAV点后的相对驻留请求，不是绝对到达时刻、跨机同步或精准悬停承诺**。上传编码、实际开始计时／位置保持／完成条件须另由真实消费者和工程验证核对，不能由秒数补造性能、续航、净空、时序或StartPermit证据。

本批仅这三文件的apply_patch与直接静读，未运行技能搜索／渲染、QML、项目、业务／parser／helper、编码器、编译、测试、仿真、设备／PX4、刷机或发布。工程需验证缺失／显式0／负零／小数／86400、错误实际类型与上下界、正值Float32／微秒归零及阈值附近请求保存失败且保输入、heading＋hold各种存在组合及末字段错误原子拒绝、旧源不补0／新源完整保存恢复、保留非激活路线、去掉勾选只移本字段、完整点回填／取消／正常＋1、过期／耗尽CAS、按下换页和换源ABA／空草稿仍可放弃、键盘／窄窗／主题／就地错误，以及真实Compiler／相对驻留编码／时间能量评估与实际读回。没有实际运行通过结论；原25目标和六类实质剩余不缩减。下方536及更早为历史。

## 536：逐辅助 NAV 航点的可选机头朝向与整点编辑

真实地图规划入口现在可对 relay／responder 的每个独立 `waypoints`／`returnPath` 点保存**可选** `heading` 原请求值。缺字段表示不发送显式朝向、沿飞控策略；显式数值 `0` 是朝北请求，两者不等价。范围是实际有限数值 `[0,360)`，沿共享 [HeadingEncoding](FleetMissionHeadingEncoding.md) 的 Int／UInt／LongLong／ULongLong／Double 接受域；字符串、Bool、null、Float、自定义值、非有限值、负值和360均拒绝。编辑 API 可用 `heading` 或 `yaw`；两者并存必须分别合法且原数值完全相等，规范只保存 `heading`，不靠 epsilon 合并。其它未知键与原坐标混合别名仍拒绝。

`pointValue` 只在**独立路线点**明确开启这一可选字段。区域顶点、排除环、`start`／`returnTo` 端点仍拒绝 heading／yaw；起飞、降落及自动生成覆盖航点不由本编辑器添朝向。`settings.headingDegrees` 始终只是扫描线方位角，不能借它补成机头朝向。旧没有 heading 的草稿和任务逐值保持，不默认补0。原 outer source schema1..6 继续仅按原 settings optional 选择，不引入无关全局升级；旧版本完整点 validator 会拒绝新额外字段，不应删 heading 冒充旧源可兼容。

规范存储路线点为原 `{latitude,longitude,altitude,coordinateSystem:'geodetic',altitudeReference:'amsl'}`，独立可选 `heading`。stored source 只收此 canonical spelling，不收 `yaw`；对全体保留路线（含暂时非激活角色）逐点完整验证，再一次安装。append、角色／名单保留、`planningSource`、editing／planning 两 validator、pristine restore 和 `buildTask` 的实际 assignments 都携原连续请求；没有分离的有损导出，也不把上传量化值反写草稿。保存／历史外层仍依这一相同 source validator，不能靠跳过新点字段读入。

新增 `updateMemberWaypoint(vehicleId,index,point,returnPath,expectedRevision)` 是一处完整点替换：现有 relay／responder、有效原路线索引、精确当前未耗尽 revision、整点坐标／可选朝向全部合法后，复用原单次 commit。遗漏 heading 明确移除该点原显式请求，不是保留旧值。点数／顺序和其它点不变；invalid-last-field、过期 revision 或其它错误均不提交。相同规范值不升 revision。原 append 仍受256点／路线、4096总保留点预算；update不增加预算。任何通知重入／销毁导致的false都不能被解释成已提交内容回滚或自动重试依据。

Planner 的辅助路线表逐点显示原朝向请求，或文字“沿飞控策略（不是0°）”。“编辑”回填该点完整坐标及独立勾选项；“保存本点修改”按原索引整点替换，“放弃本点输入”只丢未提交文本，不删除／重排原点。新增点同样支持显式勾选后输入数值；未勾选不发送 heading。真实 append／update／remove 窄 facade 现在均要求捕获的 `expectedRevision` 和 `expectedSourceToken`，在旧审阅失效的通知前后核原 native Draft、selection、版本和来源，再调用原对象，调用后不自动转用新草稿。UI 输入会话另保原 controller／facade／sourceToken／selection／revision／member／path／index；编辑／删除按钮在按下时捕获来源和原行，点击再核，跨页／换源不改新行。换源或中途版本变化保留输入但拒保存，须明确放弃再重选；即使新草稿无成员或非辅助角色，旧输入及放弃按钮仍可见。仅有朝向修改也算未提交输入，不能沿旧值预览、批准、保存或切成员／路径。

输入使用原 QGC palette／控件，独立可见 label、键盘焦点、滚动可见性、字段旁错误和可操作放弃按钮；新增控件不靠颜色单独表示有效性。朝向输入在失焦／保存后显示就地范围错误。说明持续区分：上传按最近 **1/256°** 网格编码（约0.004°，近360°可能编码为0°），这是**编码步长，不是实飞精度或已完成转向证明**；原请求／实际量化在真实上传审阅展示，飞控自身策略仍可能覆盖。Planner不另实现一份量化或读回容差算法，不借请求声明认证转弯几何、飞行时序、实际参数或StartPermit。

本批仅 apply_patch 和直接静态阅读；未执行搜索脚本、渲染／QML、项目、业务／解析器／helper、编译、测试、仿真、硬件、刷机或发布。工程需验证缺省／显式0／任意非cardinal值／近360、合法相同双别名和不等／非法别名、各数型／错误容器、只改heading／取消显式请求、旧无heading源逐值保持、新源完整保存恢复、末点错误原子拒绝、保留非激活路线、noop／过期／耗尽CAS、换源ABA／通知销毁与错误后不自动重试、键盘／窄宽／主题／焦点、实际Compiler／payload／上传审阅／真实PX4回读原值保留及声明网格语义比较贯通（非逐位相同）。以下均为历史描述，不覆盖本节逐点增量；原25目标和六类实质剩余继续未完整闭环。

## 521：完整性能准入政策、显式数值下限与source schema6

普通区域Draft现在可保留后端已有的两项任务根准入输入：可选 `minimumSpeedMps`（m/s）与 `minimumEnduranceSeconds`（s）。两者都只接受实际非null的Int／UInt／LongLong／ULongLong／Double数值，必须有限且在 `0..9007199254740991` 内，规范存为Double；字符串、Bool、Float／custom值、null／typed-null、非有限值和域外值整次拒绝，不舍入、不截断。`0` 是显式保留的下限，与缺字段不同。它们是任务声明的性能要求，不是观测性能、构型认证、实际续航、能量承诺或StartPermit。

完整 `configure(settings)` 仍为全替换：原11必需键，加原 `clearanceInput`／`exclusionPolygons`／`boundarySetbackMeters` 三个独立optional及 `requirePerformanceEvidence`／两个floor，最多17键。缺任何必需键、出现未知键或任一optional无效均不提交；漏掉optional明确移除它，不从旧设置、机型或其它成员补值。构造默认仍只有原11键，不补strict Bool或floor。

新增 `setPerformanceAdmissionPolicy(policy,expectedRevision)` 返回Bool。`policy` 的native形参是QVariant，必须为实际非null Map，且只可有0..3个已知optional键：`requirePerformanceEvidence`（实际非null Bool）、`minimumSpeedMps`、`minimumEnduranceSeconds`。它一次**替换仅这三个政策键**：缺键移除，实际空Map清三键，未知键／错误容器／无效最后字段原子拒绝；所有其它settings、成员、保留profile与几何保持。两个floor可独立存在，不强制带strict Bool，也不将strict缺省替为false。

该CAS要求实际数值的精确当前未耗尽revision，复用完整settings归一化与原单次commit；相同规范值不升revision，真实内容变化只升一次。内容与revision先提交，再发原错误／changed通知；通知可删对象或改出新revision，因此false可能发生在真实提交之后，不能当回滚或自动重试。旧 `setPerformanceEvidencePolicy`／`clearPerformanceEvidencePolicy` 仍只设置／移除Bool，必须保留两个floor，不借旧按钮暗清新要求。

`planningSource` 仍exact5 `{schemaVersion,sourceRevision,vertices,members,settings}`。版本按**字段存在**选择，先floor再旧优先序：

- 任意一个floor存在（包括显式0）即schema6，允许strict Bool和原三个optional任意组合；6却没有任一floor拒绝。
- 没有floor时，strict Bool存在才schema5；再按setback／exclusions／clearance分别为4／3／2，否则1。schema1..5携floor一律拒绝，不降级或丢字段；原1..5的版本与optional关系不变。

`buildTask` 只在settings实际存在时把三个政策键逐项放入真实任务根；显式0／false保留，缺省不输出。原带planningSource的9键任务最多再加reservePlans与这三个政策键（最多13键）；中央planning validator去掉planningSource后相应最多12键。此类声明不增加成员字段，不改变coverage速度，也不自动开strict政策、补性能来源或放行。下游实际Compiler／能力和能量消费者仍决定要求是否满足；保存／归档／余项恢复通过同一完整source validator保值，不另造一份floor来源。

editing与planning两种validator共用schema6规则，但仍分别保留“有界未完成草稿”和“完整可构建任务”的旧差异。pristine-only load仍只在新实例原子保留全部输入，设本地revision1并撤 `mapDatumAcknowledged` 确认，不恢复原revision、审阅、批准、设备证据或权限。旧软件会拒绝schema6，不应靠剥两个floor重存为旧schema获得旧审阅身份。

本批仅源码编辑、直接静读与普通文本核对；未编译、执行项目／helper／解析器／业务／QML／测试、仿真或硬件操作。需工程验证absent／0／正数及上下界、Bool/string/null/Float/无穷错误、任一floor与strict缺省／false／true、schema6和旧schema错配、完整configure与三键CAS原子性、noop／过期／耗尽revision、通知重入／销毁、旧strict开关保floor、编辑／保存／归档／余项完整往返及实际Compiler要求拒绝。以下段落为历史，不覆盖本节版本与字段合同；原25目标和最终StartPermit边界不变。

## 485：可选严格性能政策与schema5完整来源

settings接受原11必需键、原clearanceInput／exclusionPolygons／boundarySetbackMeters三个可选键，以及新可选 `requirePerformanceEvidence` 实际非null Bool，最多15键。只要新键存在，true和false都为source schema5；5必须带该键，旧1..4带键拒绝。5允许原三optional的任意组合；未声明的旧来源保持原1/2/3/4优先序和输出，不补false或true。来源仍exact5，editing/planning validator与load共用同一规则。

## 477: atomic retained area policy and explicit nominal-setback source version 4

`settings.boundarySetbackMeters` is a new **optional** actual finite numeric setting from 0 to 500 metres. Numeric strings, booleans, null/typed-null, non-finite, negative or larger values reject without changing the retained input. The constructor still emits only the original 11 base settings: no setback, exclusion declaration or clearance input is invented. The value is a declared common nominal horizontal planning requirement, not measured vehicle size, positioning/tracking error, an authenticated obstacle boundary, certified clearance, flight eligibility or permission.

The native source still has exactly five outer fields `{schemaVersion, sourceRevision, vertices, members, settings}`. Presence is versioned rather than inferred from a positive value:

- Schema 1: the original 11 settings, no optional inputs.
- Schema 2: the original settings plus complete `clearanceInput`, with no exclusions or setback.
- Schema 3: a present `exclusionPolygons` declaration, optionally complete `clearanceInput`, and **no** setback key. Explicit `[]` remains present.
- Schema 4: a present `boundarySetbackMeters` key, including explicit `0`, with independently optional `exclusionPolygons` and `clearanceInput`. Margin-only settings are supported, so clearing the exclusions does not delete an independently retained setback.

Both `validateEditingSource` and `validatePlanningSource` enforce that exact version/presence coupling and retain the full canonical setting. A schema 1/2/3 source with a setback key, schema 4 without it, or schema 3 without exclusions is rejected; no new policy is silently stripped to make an old source load. Schema 1/2/3 input without the new key keeps its previous source and task representation. Explicit zero has legacy nominal geometry semantics but a distinct schema-4 source/task identity: it is not normalized into absence. The two validation modes keep their original distinction between bounded unfinished editing state and a complete buildable proposal.

`setAreaPlanningPolicy(policy, expectedRevision)` is one new QML-invokable atomic edit. `policy` must be an actual non-null Map with exactly `{exclusionPolygons, optional boundarySetbackMeters}`. The complete exclusion list is required, including a deliberate empty List, and uses the original 8-ring/64-points-per-ring/128-total-retained-boundary budget and canonicalization. The optional setback is independently validated. Missing setback **explicitly removes** the old setback; it does not mean merge or preserve. Missing exclusions, extra fields, aliases, wrong containers or invalid last fields reject the entire proposed edit. There is no intermediate native state containing new holes and the old margin, or vice versa.

This edit requires the exact current unexhausted numeric revision and uses the existing shared `commit` path. All candidate settings are normalized and the full outer-plus-exclusions budget is checked before commit. Existing member order, inactive member input, complete clearance declaration, datum acknowledgement and all unrelated settings remain unchanged. A canonically unchanged edit does not consume a revision. As with existing edits, `lastErrorChanged` / `changed` handlers may destroy or supersede the draft after a real commit, so a returned false must not be interpreted as rollback or automatically retried.

`configure(settings)` remains complete replacement of all 11 base settings plus only the three independent optional inputs; omitting any removes it. The old `setExclusionPolygons` still replaces only holes and preserves a retained setback. `clearExclusionPolygons` removes only the holes, preserving setback/schema 4; clearance set/clear likewise preserves both area settings. To remove a margin atomically while retaining holes, submit the complete policy without its optional setback. Explicit `0` is a retained policy, not a removal request.

`buildTask(expectedRevision)` copies a present setback into **`task.area.boundarySetbackMeters`**, alongside present `area.holes`, never into coverage-only options or a new top-level task key. Existing task shape remains eight base fields without `planningSource`, or nine with `reservePlans`. The actual Compiler reconstructs and compares the complete area from a valid planning source, keeps the full raw task in plan identity, and invokes the shared [FleetAreaCoveragePlanner](FleetAreaCoveragePlanner.md) final-route policy check on the actual compiled outbound/return/join and complete reserve-budget routes. Rejected edits leave content/revision unchanged, so the controller/UI must separately invalidate review on a rejected user edit. Integer revisions never wrap: the instance refuses changes or task builds at 2^53; a new instance is needed after exhaustion. Large 64-bit integer inputs outside the exactly representable revision range are rejected before conversion.

`buildTask(expectedRevision)` requires an exact numeric integer revision and returns `{ok, draftRevision, task, errors, manualConfirmationRequired: true, flightCommandReleased: false}`. Errors have `{field, message}` for inline display; a failure contains no partial task. Build emits no signals and performs no downstream compilation. A successful task contains:

- `area`: explicitly geodetic vertices, plus complete optional `holes` only when the draft explicitly retains `exclusionPolygons`.
- `coverage`: geodetic/AMSL survey parameters, all scout/leader participant IDs, and optionally canonical decimal-ID keyed `vehicleEndpoints`. UI `laneSpacingMeters` / `speedMetersPerSecond` map to the helper's actual `spacingMeters` / `cruiseSpeedMetersPerSecond` keys.
- `assignments`: non-reserve members with explicit geodetic/AMSL metadata and `returnRequired: true`. Relay/responder geometry has `timingEvidence` and `returnTimingEvidence` equal to `unknown`; no task duration budget is promoted into authoritative timing.
- `vehicleCount` counts non-reserve assignments; `reserveVehicleIds` / `reserveCount` are separate. Explicit constraints include an AMSL maximum altitude and top-level `returnReserveSeconds`. The task area is not treated as a certified operational geofence (`geofenceRequired: false`). Active endpoint/auxiliary altitudes above the declared AMSL ceiling block build.
- `planningSource` retains the complete five-field original editing snapshot described in 427/448/476, with schema 1/2/3 selected by explicit optional-input presence, not reconstructed compiled geometry or review authority.

With endpoint mode disabled, a scout/leader has no generated return path; downstream return/energy/airspace review remains responsible for blocking missing evidence. Even with endpoints enabled, generated ingress/return geometry remains unverified and has only estimated timing. The model cannot remove those review blockers by accepting a map declaration.

## Map/editor integration

`GuidedActionsController` owns the only internal draft instance; panels use its narrow `missionDraft` edit facade and value snapshots. The command-center entry opens `FleetMissionPlannerPanel`. Capture the current selection explicitly, then select a member to edit its role/endpoints or independent auxiliary routes. Numeric fields have visible labels and strict decimal parsing; unfinished fields invalidate old review immediately, and preview submits all settings atomically. Uncommitted coordinates or a pending roster replacement cannot silently fall back to earlier saved input. Close/reopen keeps the current UI-session draft/text, not a restart-persistent draft.

Map-picking mode is compact; right-click adds a vertex and dragging pans. Keyboard coordinate input remains an alternative. The entire planner-open period blocks the old map action menu, Goto and Shift queue entry/confirmation/dispatch boundaries. Each pointer press captures the planning epoch; an open/close during the gesture drops it. Opening also cancels old confirmations and suspends automatic first-location centering, tracking animations and new-mission viewport fitting. Separate manual safety controls are not globally disabled. These are source-level guards, not proof of hostile-plugin isolation.

Map paths and member summaries use only `missionReview.plan.members`, not the separate automatic capability preview or role-allocation suggestions. Full outbound/return views are limited to 8192 total points; invalid/oversized views are not drawn as a prefix. Auxiliary input lists use 12-point pages. Routes are geometric proposals without clearance or certified timing. Input edits and failed/no-op mutation requests invalidate the previous review; the controller captures draft revision/edit generation, checks the returned live archive binding, and approvals require the displayed `draftRevision` and `recordId`. Existing health/configuration/store gates still apply, and confirming a plan never dispatches it. Generated timing remains unknown to authoritative 4D review, so merely checking the coordinate declaration cannot make a blocked proposal approvable.

The QML type/resource, internal native type and qmake source/header registration are wired in the current worktree. UI uses existing QGC palette/controls and platform-independent label, keyboard-alternative and visible-error guidance; no new web styling, external fonts or assets. Layout, contrast, focus, popup stacking and gesture behavior have not been runtime-verified.
